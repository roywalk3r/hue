Playback

Simple outside, resilient inside

Normal viewers should never have to pick a provider. The app can keep technical playback detail behind a support drawer.

  • Preparing stream, checking sources, playing, trying another source, unavailable, and browser playback issue states.
  • Season and episode selector, subtitles, autoplay preference, quality preference, and next episode.
  • Automatic source fallback before showing an error.
  • Advanced playback details hidden unless needed for support.
Build path

Hosted product plan

Build a dedicated Nuxt frontend hosted as the public app, with the current Hue backend kept as a private aggregation API behind a BFF layer.

01

Backend hardening

Fix streams crash, auth routes, password flow, SSRF, proxy-disabled play, and secrets.

02

Nuxt BFF

Normalize backend provider payloads into `/v1/home`, `/v1/search`, `/v1/title`, `/v1/play`, and `/v1/live`.

03

Frontend MVP

Home, browse, search, detail, watch, live, and saved list with real backend data.

04

Polish

Motion, visual QA, mobile fit, playback fallbacks, and hosting checks.

05

Launch

Public app domain, persistent API host, separate locked admin surface, smoke checks.

Hosting topology

Public product, private core

The frontend should not expose backend internals directly. Nuxt presents a stable consumer API while the existing Express backend remains the aggregation engine.

app

Frontend

`app.example.com` or main domain. Nuxt, premium UX, search, watch, saved, live.

bff

Consumer API

Nuxt server routes normalize provider payloads and protect frontend assumptions.

api

Hue backend

`api.example.com` on a persistent host for scraping, workers, proxying, and cache.

admin

Operator UI

Separate locked admin surface, never primary navigation for viewers.

stream

Media proxy

Optional isolated domain if bandwidth, CORS, or abuse controls need separation.
