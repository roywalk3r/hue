# HiTV Decryption & Sign Algorithm

Reverse-engineered from HiTV's Nuxt 2 webpack bundle (May 2026).

## Architecture

HiTV uses two layers of protection:

| Layer | Mechanism | Location | Status |
|-------|-----------|----------|--------|
| Transport | AES-128-CBC | All `/s1/w/` API responses | Cracked |
| Stream auth | MD5 sign | `/s1/w/series/api/series/rslv` query param | Cracked |

## Layer 1: AES Transport Encryption

### Algorithm

```
encrypted_response = { ts: <unix epoch>, data: "<base64 ciphertext>" }

decryption_key = MD5(MD5(did + ts) + SALT)[0:16]
iv             = MD5(MD5(did + ts) + SALT)[16:32]

plaintext = AES-128-CBC_decrypt(base64_decode(data), key, iv)
```

- `did` — device ID, sent as both `did` request header and `hpwa_did` cookie (same value)
- `SALT` — constant: `Wcb26arWkvkcAZc378eR`
- `ts` — Unix timestamp from response body

### Discovery

Traced by intercepting Playwright network requests on `https://home.hitv.vip/gallery`. The Nuxt app's webpack chunk 65 (`65.b63c53621a2c75023942.js`) contains the crypto-js AES decryption in module 903, and the SALT retrieval in module 902 via the base64 utility module.

## Layer 2: Stream Sign Generation

### Algorithm

```
sign = MD5("eid=<eid>&scid=<scid>&sid=<sid>&sq=<sq>&appkey=<appkey>")
```

- `eid` — episode ID (e.g. `e_f2prDoHCi7Oadj6HElLT`)
- `sid` — series ID (e.g. `s_e9lVHR8cOe186nZinQYfX`)
- `scid` — source config ID (e.g. `sc_TgAZFOAyuC4FY6p7t_Fd`)
- `sq` — sequence number (typically `1`)
- `appkey` — constant: `bywebabcd1234`

### Discovery

The sign is generated by the Vuex action `series/getSeriesPlaySource` in chunk 65. The obfuscated flow:

```
1. Vue component dispatches getSeriesPlaySource with p1..p5
2. Chunk 3 (module 498): getPlayLink() dispatches with:
   p1=eid, p2=sid, p3=scid, p4=sq, p5=I.a()
3. Chunk 55 (module 1680): I.a() = f.b("bywebabcd1234")
4. Chunk 29 (module 151): f.b = base64_encode, f.a = base64_decode
5. Chunk 65: v() constructs the param string:
   - f.b("appkey") → base64("appkey") → stored as m
   - f.a(m) → base64_decode(m) → "appkey" (obfuscation, cancels out)
   - f.a(p5) → base64_decode(p5) → "bywebabcd1234"
6. o() = md5 (module 674)
7. sign = md5(v(eid, sid, scid, sq, p5))
```

### Chunk Map

| Chunk | Module | Export | Purpose |
|-------|--------|--------|---------|
| `29.*.js` | 151 | `a = base64_decode`, `b = base64_encode` | Encoding utilities |
| `3.*.js` | 498 | `getPlayLink()` | Player component, dispatches action |
| `55.*.js` | 1680 | `I.a()` | Returns `base64("bywebabcd1234")` = appkey |
| `65.*.js` | 903 | AES decrypt | CryptoJS AES-128-CBC |
| `65.*.js` | 902 | SALT getter | `f.b("Wcb26arWkvkcAZc378eR")` |
| `65.*.js` | 1721 | `getSeriesPlaySource` | Vuex action, calls v() + md5 |

### Key Rotation

If HiTV rotates the `appkey`, update `HITV_APPKEY` environment variable or call `hitv.fetchAppkey()` which dynamically extracts the current value from HiTV's CDN by intercepting chunk loads on a series page.

To find the new value manually:

1. Visit `https://home.hitv.vip/series/perfect-crown` with DevTools open
2. Search loaded chunks for `1680:function`
3. The string inside `Object(n.b)("...")` is the base64-encoded appkey
4. Decode it: `atob("<value>")` or `Buffer.from("<value>", "base64").toString("utf8")`

## Usage

```js
const hitv = require('./utils/hitv');

// Browse gallery
const series = await hitv.gallery({ location: 5, genre: 3, page: 1 });

// List episodes
const episodes = await hitv.episodes(seriesId);

// Get episode detail (includes stream sources)
const detail = await hitv.episodeDetail(eid);

// Resolve stream — sign auto-generated if sid+scid provided
const streams = await hitv.streams(eid, sid, scid, quality);

// Generate sign directly
const sign = hitv.generateSign(eid, sid, scid, sq);

// Rotate appkey at runtime
const freshKey = await hitv.fetchAppkey();
const sign2 = hitv.generateSign(eid, sid, scid, sq, freshKey);
```
